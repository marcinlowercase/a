1. Executive Summary

This report evaluates zero-cost Large Language Model (LLM) code generation for the browser of oo1 studio (v1.7, Android + Mozilla GeckoView runtime) using the consultative refine System Prompt SDK (Deliverable 3) across all three controlled small-business use cases defined in Task 6. Under the consultative SDK, a standard generation session involves initial code output followed by 2–3 iterative refinement turns to adjust layout and behaviour to the user's exact needs.

Key finding: Even at zero cost, platform context capacity directly dictates workflow reliability. Using Google AI Studio (aistudio.google.com, a free professional developer workbench running gemini 4 hydrogen with a 1M-token context window), the model preserved the full SDK rules and both HTML reference templates across the initial build and all 2–3 iterative refinement turns, achieving a 3/3 (100%) pass rate across all use cases with zero template re-injection required.

By contrast, ChatGPT (free-tier consumer mobile/web chatbot) suffered from a shorter active context window, dropping the two few-shot HTML reference templates before compilation on all 3 use cases (0/3 single-paste retention). Once the templates were manually re-pasted prior to compilation, ChatGPT followed the standard 2–3 refinement workflow and succeeded on 2/3 use cases (UC1 and UC3 passed cleanly). On UC2 (Client Intake Manager), ChatGPT's JavaScript logic functioned properly, but it failed strict template layout fidelity (~60–70% fidelity on initial build due to uneven tile sizes, degrading to ~30–40% unstyled grid after requesting uniform 1x1 sizing). All 6 generated applications passed runtime security sandbox enforcement within v1.7.

4. UX & Security Sandbox Evaluation (v1.7)

  • Mobile TUI Wireframe Optimization: Early TUI examples placed descriptive text inside grid cells, wrapping poorly on narrow phone screens. Updating the SDK to a compact numbered grid (≤ 26 characters wide with numbered specifications underneath) kept TUI confirmation readable on mobile viewports prior to compilation.
  • Strict Folder & Origin Isolation: In v1.7, every installed application runs inside an isolated local://apps/<slug> origin. Applications can only create and operate within their own dedicated folder scope on device storage and inside Google Drive (appId partitioned folders), preventing cross-app data snooping or root directory traversal.
  • Mandatory Runtime Permission Gating: Regardless of whether code was compiled by Gemini or ChatGPT, the first time an app requests to save a file to Google Drive, write to local storage, or start the CameraX stream, the browser intercepts the bridge call via CustomPermissionDelegate and surfaces a native user-consent permission panel before execution.

5. Conclusions & SDK Recommendations

Conclusion: Google AI Studio (gemini 4 hydrogen, free tier) is the recommended runtime partner for users building apps with the refine SDK, delivering 100% (3/3) functional and layout accuracy across standard 2–3 turn refinement loops with zero template re-pasting required. While ChatGPT (free consumer tier) generated valid JavaScript logic across all three use cases once templates were re-injected (passing UC1 and UC3 cleanly), its shorter context window caused multi-turn template amnesia and layout degradation during iterative CSS edits on UC2. Security isolation in v1.7 passed 100% across all outputs from both models.
  • Developer Workbench vs. Consumer Chatbot: Even though both tools are free to end users, Google AI Studio's 1M-token context retention vastly outperforms general consumer free-tier chat sessions when holding multi-hundred-line HTML/CSS few-shot templates across iterative refinement turns.
  • SDK Mitigation for Short-Context Chatbots: When running on ChatGPT free tier or similar short-context mobile chatbots, instruct users to re-attach the HTML reference shell directly on the final compilation/edit turn (or host the immutable grid CSS inside the local runtime shell) so layout styling is never truncated during iterative edits.
